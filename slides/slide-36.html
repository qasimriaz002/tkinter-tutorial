Postgres Database & GUI

1. database.ini

Instead of hardcoding passwords in your script, we use a configuration file. This is a standard security practice.

[postgresql] host=localhost database=university user=postgres password=secret123

2. Config Parsing & psycopg2

  • configparser: A built-in Python module used to read .ini files.
  • psycopg2: The most popular PostgreSQL adapter for Python. It translates Python objects into SQL queries.
  • Connection Pipeline: Python reads database.ini -> Parses credentials -> Passes them to psycopg2.connect() -> Establishes TCP connection to Postgres Server.

3. CRUD Operations

Just like SQLite, we use cursor.execute(). However, Postgres uses a slightly stricter SQL dialect for specific data types (e.g., SERIAL for auto-increment) and handles transactions differently (requires explicit commit for DDL usually).

Code Explanation:

1. Configuration & Connection

  • ConfigParser(): Reads the database.ini file. This decouples the code from the credentials, allowing you to deploy the same script to different servers without changing the Python code.
  • psycopg2.connect(**params): Uses Python's "dictionary unpacking" to pass the parsed credentials (host, user, password) directly to the connection function.

2. Postgres SQL Syntax

  • Placeholders: SQLite uses ?. Postgres requires %s as the placeholder for parameter substitution.
  • Transactions: Postgres is transactional by default. If you don't execute conn.commit(), your INSERT or DELETE commands will be rolled back (undone) when the script ends.

3. GUI Integration

  • The GUI logic is identical to the SQLite version. This demonstrates a key principle: Separation of Concerns. The GUI only talks to the Python functions; it doesn't care if the data comes from a local file or a remote server.
