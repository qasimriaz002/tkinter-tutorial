No-SQL Databases & Concepts

1. What is No-SQL?

Not Only SQL. No-SQL databases provide a mechanism for storage and retrieval of data that is modeled in means other than the tabular relations used in relational databases. They are optimized for specific data models and access patterns.

2. Need for No-SQL?

  • Unstructured Data: Social media feeds, IoT logs, and chat logs don't fit well into rigid tables.
  • Scalability: They scale horizontally (adding more servers) easily, whereas SQL often scales vertically (adding more power to one server).
  • Speed: High performance for simple read/write operations without complex joins.

3. Difference B/W SQL and No-SQL

SQL (Relational)
- Tables & Rows
- Fixed Schema
- Vertically Scalable
- ACID Properties
No-SQL (Non-Relational)
- Documents / Key-Value / Graph
- Dynamic / Schema-less
- Horizontally Scalable
- BASE Properties (Eventual Consistency)

4. Tree Structure (JSON)

Unlike SQL tables, NoSQL (like Firebase or MongoDB) often stores data as a tree of nodes or JSON documents.

5. Key Concepts

Schema-less: You don't need to pre-define columns. Document Store: Data is stored as JSON documents (e.g., MongoDB). Real-time Sync: Listeners update data instantly when it changes on the server (e.g., Firebase).

6. Types of No-SQL

  • Document: MongoDB, CouchDB (Stores JSON).
  • Key-Value: Redis, DynamoDB (Fast lookups).
  • Column-family: Cassandra (Wide columns).
  • Graph: Neo4j (Relationships).

10. Firebase Realtime DB Example

import firebase_admin from firebase_admin import credentials, db # Initialize the App with key.json cred = credentials.Certificate("serviceAccountKey.json") firebase_admin.initialize_app(cred, { 'databaseURL': 'https://my-app.firebaseio.com' }) # Reference the database ref = db.reference('users') # INSERT: Push new data ref.push({ 'name': 'John Doe', 'age': 30 }) # RETRIEVE: Get all data users = ref.get() for key, user in users.items(): print(user['name'])

Code Explanation:

1. Credentials: credentials.Certificate("key.json") loads the private key from the file to generate an authentication token.

2. Initialization: initialize_app creates the connection to the specific database URL.

3. Reference: db.reference('users') points to the specific "node" in the database tree (similar to a folder path).

4. Operations: push() adds a new record with a unique key. get() fetches the snapshot of the data at that node.
